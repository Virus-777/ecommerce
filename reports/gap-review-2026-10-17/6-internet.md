# Marketly internet-dependency audit (section E in depth)

## Executive summary
1. **The backend makes one outbound internet call in its runtime code**: the Cloudflare Turnstile check (`backend:src/kernel/auth/app-proof.ts:54`). It runs only when `TURNSTILE_SECRET` is set and the caller is outside the LAN. The production template leaves it unset and sets `APP_PROOF_LOCAL_NETWORK=true`, so the offline server never makes the call.
2. **Every provider port is wired to an in-process dev stub in every environment, production included.** That covers payments, payouts, carriers, email, SMS, push, tax, KYC/KYB, payout tokenising, malware scan and video transcoding. None of them uses the network, so nothing blocks startup, no job retries forever and nothing waits on a timeout. The offline server is safe. The online product has no real providers at all.
3. Google and Apple sign-in, and address validation, are wired only when `DEV_TOKENS` is on. In production they are `undefined`: sign-in with Google or Apple answers 501, and addresses get format checks only.
4. **Deployment is fully offline by design.** Node, MongoDB and the release tarball (which contains `node_modules`, with sharp's Linux binaries pre-installed and install scripts skipped) all come over on USB. No apt repository, NodeSource, certbot or npm is used on the server. The certificate comes from a local CA built with openssl.
5. **Nothing sets up time sync.** On an offline Ubuntu server, timesyncd cannot reach `ntp.ubuntu.com`, so the clock drifts. This affects certificate validity on staff PCs, token expiry, scheduled jobs and audit times.
6. **The Admin Center is clean for offline use.** Its fonts are bundled, it loads nothing from a CDN, and its CSP is `default-src 'self'`. The built `dist` contains no external fetch.
7. The Customer Store and Seller Center load Google Fonts in `index.html`. That is acceptable online, but offline they fall back to system fonts, and they are not served by the offline server anyway. Neither app has a Turnstile widget: they always send the app proof `dev`, which **production refuses for any caller outside the LAN**.
8. **Data in both local databases (27017 and 27018) points at local hosts only.** Product and media images are served from the API's own `/files`, and no DummyJSON or Open Food Facts image hosts are left. The only internet hosts stored are carrier tracking links (ups.com, usps.com, fedex.com), the Play Store update link, and example.com placeholders.
9. **Features that degrade offline:**
   - Carrier "track" links are dead.
   - Email-based features (scheduled report emails, "the applicant gets your explanation by email", inbox email copies) silently go nowhere. The dev email provider runs in production, records messages in memory and marks them `delivered`.
   - Video ad assets never finish processing, because no transcode result ever arrives.
10. **Must-fix list for offline: 6 items, none blocking startup.** The most important are time sync, accurate "email" wording and delivery status, and video assets that stay in processing.

Sections A–D: skipped (outside this reviewer's scope). Section E counts: backend runtime 21 rows, backend tooling/deploy/OS 11 rows, frontend 17 rows, data 6 rows.

Legend for offline behaviour: **works** = no internet needed · **degrades** = feature partly unavailable, rest fine · **breaks** = feature unusable · **blocks startup** = server won't start.

## Must fix for the offline deployment

None of these blocks startup or a core staff flow; the server is offline-clean by design.

1. **M1 (Medium): Time sync.** Add a README step (and a `marketly check` warning) to sync the clock from a LAN source with chrony or timesyncd `NTP=<router or DC>`, or to set it by hand periodically. Without it, certificate validity, token expiry, job schedules, approval deadlines and audit times drift. Evidence: nothing in `backend/deploy/linux/` or `docs/MAINTAINING.md` mentions NTP or the clock.
2. **M2 (Medium): Emails are recorded as "delivered" but never leave the server.** The dev email, SMS and push providers run in production (`backend:src/modules/notifications/module.ts:28-34`, `providers/email.ts:26`). Admin copy promises emails (`admin-center/src/pages/admin/Reports.tsx:59,98`, `SellerApplication.tsx:251`, `Inbox.tsx:269`).
   - Add an explicit offline provider whose status is `not_sent` or `offline` instead of `delivered`, and expose a flag so the Admin Center hides "Schedule email" and rewords "by email".
   - Seller decisions currently reach applicants only if staff contact them another way.
3. **M3 (Low): Carrier tracking buttons in the Admin Center open internet sites** (`admin-center/src/pages/admin/Order.tsx:379-380`, URLs from `backend:src/modules/shipping/domain/tracking.ts:34-65`). Hide them, or show the tracking number with "needs internet".

Refuse video purposes offline, keep the original file without transcoding, or add a local ffmpeg processor. Also add a timeout that marks stuck transcodes as failed.
